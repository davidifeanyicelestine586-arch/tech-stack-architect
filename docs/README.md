## Documentation principles

- Keep portfolio-facing documentation concise and outcome-focused.
- Avoid publishing secrets, credentials, private infrastructure details, or unnecessary security implementation details.
- Keep historical engineering notes when they provide useful project context, but do not treat them as the primary product documentation.
- Update public documentation when setup, usage, deployment, or supported behavior changes.
